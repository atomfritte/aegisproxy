What was broken in 1.x

The most serious findings. All are fixed and covered by automated tests; the complete list of 19 is in docs/security.md.

SeverityFindingFix
criticalHard-coded JWT secret and data-plane key: anyone could forge admin sessions or impersonate a proxy worker.Per-installation secrets; known defaults rejected at start.
criticalPolicy checked the Host header while mitmproxy connected to the real destination.Evaluate request.host; Host/SNI mismatches blocked.
criticalTLS no-break exceptions never worked (ignore_conn instead of ignore_connection).Fixed, plus SNI must equal the CONNECT target.
criticalNon-HTTP traffic (SSH, exfiltration) relayed through CONNECT tunnels.rawtcp=false: no upstream connection is ever opened.
criticalFail-open when the control-plane was unreachable; import errors silently disabled the addon.Fail-closed before the first sync; start-up aborts on errors.
criticalPassword hashes were never saved: nobody could log in after a restart.PBKDF2-SHA256 (600k), transparent re-hash, bootstrap admin.
highServer proxy tokens leaked to upstream sites and stored in plaintext; token auth never applied to HTTPS.Header stripped, SHA-256 storage, identity captured at CONNECT.
highAnyone could file access requests in another server's name.Requests carry a proxy-signed block token, else flagged “unverified”.

New threat protection

Threat intelligence

abuse.ch Feodo and SSLBL, Spamhaus DROP, Emerging Threats, URLhaus domains, ransomware domains, plus custom IOCs and false-positive exceptions. Checked against host names, URLs, resolved IPs and file hashes.

Antivirus and download control

Downloads streamed to ClamAV (caught EICAR in testing). File types such as executables, scripts and Office macros can be blocked per server group.

Data loss prevention

Private keys, cloud and API tokens, card numbers (Luhn-checked) and /etc/shadow in outbound requests. Starts in report-only mode.

Destination and protocol guard

DNS-rebinding protection with IP pinning, cloud metadata always blocked, IP-literal and port policy, punycode flagging, upload limits, block-burst anomaly alerts.

threat intel→destination hygiene→BLOCK rules→TLS passthrough→learning session→redirect grant→ALLOW rules→default deny

Architecture and high availability

Control-plane replicas run active-active on PostgreSQL. Configuration changes are serialized with a row lock, so no acknowledged write is lost and the audit hash chain stays linear across nodes. Replicas learn about changes through LISTEN/NOTIFY; telemetry replicates within about a second. Data-plane workers are stateless and keep enforcing the last policy if the control-plane goes away.

Open items

  • Windows installers were syntax-checked and analysed but not yet executed on a Windows Server host; IIS hosting is untested.
  • Kubernetes NetworkPolicy enforcement still needs a test on a standard CNI. The test host runs kernel 7.2.2 with only 7.2.9 modules installed, so the cluster used an eBPF-only network that misclassified kubelet probes.
  • abuse.ch URLhaus, ThreatFox and MalwareBazaar bulk exports now need an API key; they can be added as custom feeds.
